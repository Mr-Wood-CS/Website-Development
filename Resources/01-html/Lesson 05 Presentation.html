Lesson 05

Testing and Refinement

Use evidence and feedback to improve the final website.

Today's Lesson

Test, receive feedback, and improve

Learning Intention

We will test a one-page website, use feedback, and refine it to improve usability and accessibility.

Success Criteria

  • Test the website against requirements.
  • Identify readability, link, image, and accessibility issues.
  • Use peer feedback to choose improvements.
  • Explain how a change improved the user experience.

Testing is useful when it leads to a specific improvement.

Key Words

Words we will use today

Testing

Checking whether the website works and meets the brief.

Accessibility

Designing so more people can use the website.

Feedback

Information from another person that helps improve the work.

Refinement

A change made to improve quality.

Evidence

Proof that a test or improvement happened.

Use these words when explaining your improvements.

Testing Questions

Choose tests that reveal useful problems

Context

You are testing the first draft of your Visit Edinburgh website before final submission.

  • Does it meet the brief? Check whether the page is one page, about Visit Edinburgh, and suitable for the audience.
  • Is it readable? Check headings, text size, spacing, contrast, and scanability.
  • Do links and images work? Check links, image quality, and credits.
  • Is it accessible? Check descriptions, contrast, clear language, and structure.

Good testing finds problems you can actually fix.

Accessibility

More users can use a page when the design is clear

Clear headings

Show what each section is about.

Readable text

Use text that is not too small and has enough spacing.

Strong contrast

Make sure colours are easy to read.

Useful descriptions

Images should have meaningful descriptions or credits.

Accessible design is good design.

Feedback

Specific feedback leads to better refinements

Context

A peer is testing your website. Their feedback should help you decide what to improve next.

  • Specific The transport section needs a clearer heading.
  • Linked to users Tourists might need opening times near the top.
  • Actionable Increase the contrast on this paragraph.
  • Evidence-based This link did not open when I clicked it.

"It is good" is kind, but it does not tell the designer what to improve.

Main Task

Test, collect feedback, and refine

  1. Complete a test plan.
  2. Test readability, links, images, spelling, and accessibility.
  3. Ask a peer to test your website.
  4. Record feedback and evidence.
  5. Choose at least two refinements.
  6. Make the changes and check that they worked.
Support

Use: issue, evidence, fix, retest.

Challenge

Prioritise the most important issue and justify why it matters.

Check for Understanding

Scenario

You have tested your Visit Edinburgh website and found several possible improvements.

Choose the level that stretches your thinking

1Beginning to learn
  1. Give one test for readability.
  2. Give one test for images.
2Making progress
  1. Describe one way to test links.
  2. Describe what to do after finding an error.
3Making good progress
  1. Explain identifying versus fixing an issue.
  2. Explain how to prioritise multiple errors.
4Meeting target
  1. Create and justify a mini test checklist.
  2. Evaluate one change made from peer feedback.

Start where you feel confident, then try the next level.

Exit Ticket

What evidence shows your website improved?

1Beginning to learn
  1. Name one issue you found.
2Making progress
  1. Name one issue and how you fixed it.
3Making good progress
  1. Name one issue, the fix, and how you checked it worked.
4Meeting target
  1. Evaluate how the change improved accessibility or usability.

Testing is strongest when it creates evidence for a real refinement.
